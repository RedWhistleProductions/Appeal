Appeal Module API Standard

Appeal docs

Every Appeal module must provide a Docs folder containing an HTML reference listing every script-visible function and global. Divide functions into exactly two groups: Basic and Advanced. List globals separately, including names, types, meaning, defaults, and when they change. Document dynamic names using placeholders.

Basic functions — required

Basic functions are high-level operations that use sensible default settings and work without fine tuning. Every module must have Basic functions. A developer must be able to make a game using only Basic functions across the modules needed by that game. Loading ordinary assets, selecting controls, performing gameplay operations, updating, and drawing belong on this path. Necessary content arguments such as names, files, and positions are still allowed.

The normal configured environment must supply plugin selection, initialization, resource paths, and suitable defaults. A Basic workflow must not depend on the script calling an Advanced function. If it does, improve the defaults or provide a high-level Basic operation; do not hide the dependency by relabeling a low-level function.

Advanced functions — optional

Advanced functions let script developers fine tune behavior, override defaults, manage backends, or access lower-level operations. A module need not expose Advanced functions. Keep the Advanced heading and state that none are available when the group is empty. Settings should have a useful default so callers can omit tuning.

Reference requirements

Document the exact command spelling, arguments in consumption order, types, units and valid ranges, default behavior, return values, errors, and global side effects. Distinguish script functions from plugin exports and internal C++ helpers. Put each function in one group only. Include aliases explicitly. Explain plugin limitations and mark planned behavior as unimplemented.

Window mode shortcut

Windowed Graphics plugins must provide Alt+Enter as the standard fullscreen toggle for Appeal applications, regardless of GUI/game input focus. Ignore key repeats, target the window receiving the key event, preserve its contents and restore its previous windowed geometry. Expose the same operation as the Basic command Graphics Toggle_Fullscreen Name, returning 1 on success and 0 on failure. Headless/test plugins may supply a diagnostic implementation.

Acceptance check

Demonstrate the module's normal contribution to a game using only Basic calls in the standard configured environment. Check that no Advanced setup leaks into that example. Confirm every interpreter command and published global appears in the reference. Classification of existing functions is an initial documentation pass; completing or simplifying implementations is separate work.
